## What This Repo Is

MUnit is an interactive unit-testing REPL for Maude, written entirely in Maude (rewriting logic). Users load their modules under test, start the MUnit session, and run test files of the form `munit MODULE is ASSERTIONS endu`; assertions are evaluated against the loaded module via META-LEVEL descent functions. Runs on Maude 3.5.1; no build system.

## Running It (repo-specific, non-obvious)

```bash
maude examples/add_even.maude -allow-files io.maude
```

then at the `MUnit>` prompt: `open examples/add_even_test.maude`, `q` to exit.

- `-allow-files` is mandatory — the `open` command uses Maude's `FILE` external object (flag-gated).
- Modules under test must be loaded **before** `io.maude`; the first line of `io.maude` (`load file.maude`) is a placeholder that is silently ignored when the file is missing.
- The README's claim that "munit.maude starts the I/O loop" is wrong: the loop starts with `erew run .` at the end of `io.maude` (which loads `mUnit.maude`).

## Directory Map

| Path | Role |
|---|---|
| `mUnit.maude` | Engine (pure functional modules): `UNIT-RESULT` (verdict record), `AUX` (metaterm/module utilities, bubble resolution), `MUNIT-COMMAND-PROCESSING` (`procMUnit`/`procProps` — one equation family per assertion verdict) |

## Key Patterns (deviate from typical Maude usage)

- **Two-level syntax via bubbles**: assertion arguments are captured as raw unparsed `QidList`s by bubble-hook operators in `MUNIT-GRAMMAR`; `solveBubbles(M, bubble)` re-parses them later with `metaParse` **in the module under test**. Any new assertion syntax touches both `MUNIT-SIGNATURE` (declaration) and `MUNIT-COMMAND-PROCESSING` (verdict equations).
- **Search conditions** are parsed in an on-the-fly derived module: `addInfoConds(M)` injects `@Sort@` constants, `_: sort` atoms, condition connectives, and `Bool < @Condition@` so user sorts work in conditions.
- **Verdicts are data**: every outcome (pass/fail/no-parse/invalid-argument) is a conditional equation returning `<Nat Nat QidList>` (passed, failed, report tokens incl. color codes); parse failure inside an assertion is a *reportable failure*, not an exception.
- **Descent over simulation**: all evaluation delegates to `metaReduce`/`metaSearch`/`metaParse`; hot paths (`solveBubbles`, `reduce`, module surgery ops) are `[memo]`.
- **Session = object state machine**: `MUNIT-IO` states `idle/waiting/reading/processing/executing/write&wait/write&end/finished`; terminal I/O via `getLine`/`write` messages; `erew` suspends while waiting for input.

## Verified Gotchas (see `.agents/summary/review_notes.md` for all findings)

- `***` comments in test files break the `MUNIT-GRAMMAR` parse and **silently stall** the session (no failure branch on `[parse-module]`); `tokenize` does not strip comments.
- `open` of a nonexistent file silently stalls (no `fileError` rule in `MUNIT-IO`).
- Everything in `io.maude` after the `eof` line is dead code — `loop init-munit .` references an undefined constant and never runs.
- The banner prints "s2025" due to a `\s` escape typo in `mu-banner`.
- `assertTrueMsg` is implemented but undocumented in the README; `assertEqual`/`assertDifferent` are `[comm]`.
- No CI or test runner; `examples/add_even_test.maude` is the manual smoke test.

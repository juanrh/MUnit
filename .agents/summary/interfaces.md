# MUnit — Interfaces

> User-facing and internal APIs. Generated by codebase-summary.

## User-Facing Interface

### Starting a session

```bash
maude <modules-under-test>.maude -allow-files io.maude
```

Constraints (from README + verified):
- `-allow-files` is mandatory (the `open` command uses the `FILE` external object, which is flag-gated).
- Modules under test must be loaded **before** `io.maude` (e.g. as the leading file(s) on the command line), because `io.maude` immediately enters the I/O loop.
- `io.maude`'s first line `load file.maude` is a **placeholder**: if `file.maude` does not exist it is silently ignored (verified), so it can also be edited to point at the modules under test.

### REPL commands

| Command | Behavior |
|---|---|
| `open PATH` | Read and run the test file at `PATH` (single token — no spaces). Reports totals, then returns to the prompt |
| `q` or `quit` | Print "Thanks for using MUnit!" and end the session |

Anything else prints "Error: Command not parsed." and re-prompts.

### Test-file syntax

```
munit MODULE is
  ASSERTION
  ...
endu
```

- `MODULE` must name a module loaded in the current Maude session; otherwise the report is "Error: The module is not loaded."
- Assertions are whitespace/newline-separated; **`***` comments are not supported** — they break the grammar parse and silently stall the session (verified; see `review_notes.md`).

### Assertions (as implemented in `MUNIT-SIGNATURE` / `MUNIT-COMMAND-PROCESSING`)

| Assertion | Passes when |
|---|---|
| `assertTrue(t)` | `t` reduces to `true` |
| `assertFalse(t)` | `t` reduces to `false` |
| `assertTrueMsg(t, msg)` | like `assertTrue`, but prints `---> msg` with the verdict (single-token message; **not documented in README**) |
| `assertEqual(t, t')` | both reduce to the same normal form |
| `assertDifferent(t, t')` | normal forms differ |
| `assertSort(t, s)` | normal form of `t` has exactly sort `s` |
| `assertLeqSort(t, s)` | normal form's sort `s'` satisfies `s' <= s` (same kind required; "The sort does not exist" if `s` unknown) |
| `assertNoSort(t)` | `t` is only defined at the kind level (no least sort) |
| `assertReachable(t, t')` | `t'` reachable from `t` in an unbounded `*`-search |
| `assertReachableBnd(t, t', bnd)` | reachable within `bnd` steps |
| `hasSolution(t, pat, mode, bound, cond)` | at least one `metaSearch` solution from `t` matching `pat` satisfying `cond` |
| `noSolution(t, pat, mode, bound, cond)` | no such solution |

Notes on the search assertions:
- `mode` ∈ `*` (0+ steps), `+` (1+ steps), `!` (final states) — mirrors Maude's search arrows; anything else → "Invalid search arrow."
- `bound` is `unbounded` or a natural number; otherwise "Invalid bound."
- `cond` is optional: an empty bubble means `nil`; conditions may use `=`, `:=`, `=>`, `: sort`, `/\`, and plain boolean terms (rewritten to `t = true` by `parseCond`). Condition syntax is parsed in a *copy* of the module under test extended by `addInfoConds`, so user sorts are usable in `t : Sort` atoms.

### Report format

```
N test cases were executed.

M failures.

<per-assertion lines: assertion (pretty-printed args) passed./failed. [+ details]>
```

Pretty-printing uses `metaPrettyPrint` with `mixfix number rat format`, so arguments appear with spaces around mixfix punctuation (e.g. `assertEqual (3 ,add (1 ,2 )) passed.`). Failures include details such as "Term reduced to ...", "First term reduced to ...", "The normal form is ... Its sort is ...", or "No parse for ...".

## Internal Interfaces (engine ↔ front end contract)

| Interface | Signature | Role |
|---|---|---|
| `procMUnit` | `Term -> UnitResult` | Front end hands the parsed `'munit_is_endu[...]` metaterm; engine returns the verdict record |
| `procProps` | `Module Term -> UnitResult` | Per-assertion dispatch inside the lifted module |
| `procSolution` / `noSolution` | `Module Term Term Qid Bound Condition -> UnitResult` | `metaSearch` wrappers (solution index 0) |
| `solveBubbles` / `solveBubblesCond` | `Module Term ~> Term / Condition` | Bubble → parsed term/condition in module under test |
| `addInfoConds` | `Module -> [Module]` | Module extension enabling condition syntax |
| `MUNIT-GRAMMAR`, `COMMANDS-GRAMMAR` | `-> FModule` | Grammar metaprograms consumed by `metaParse` |
| `printUR` | `UnitResult -> String` | Verdict record → user report |
| `run` | `-> Configuration` | Initial configuration for `erew run .` |

## Failure Modes (verified behavior)

| Situation | Behavior |
|---|---|
| Unparseable assertion text (bubble fails `metaParse` in module under test) | Assertion **fails** with "No parse for ..." (counted in the report) |
| Unknown module in `munit MODULE` | Report line "Error: The module is not loaded." |
| Invalid mode/bound/condition in search assertions | Assertion fails with the corresponding "Invalid ..." message |
| `***` comment or other grammar-level defect in the test file | **Silent stall** in `processing` state — no rule applies, `erew` returns, session unusable |
| `open` of a nonexistent file | **Silent stall** in `reading` state — `fileError` message is never consumed |

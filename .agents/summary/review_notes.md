# MUnit — Review Notes

> Consistency and completeness review of this documentation set. Generated by codebase-summary. All "verified" items were confirmed empirically against Maude 3.5.1 running this repository.

## Consistency Findings (documentation ↔ code ↔ README)

| # | Finding | Severity | Detail |
|---|---|---|---|
| C1 | README names the wrong entry file | Medium | README says "the **munit.maude** file, which starts the I/O loop". No file named `munit.maude` exists; the I/O loop starts in `io.maude`, which `load`s `mUnit.maude` (note capitalization: `mUnit.maude`). |
| C2 | README omits one implemented assertion | Low | `assertTrueMsg(t, msg)` is declared in `MUNIT-SIGNATURE` and fully processed in `MUNIT-COMMAND-PROCESSING`, but is absent from the README's assertion list. |
| C3 | README output is stylized | Low | Actual report lines come from `metaPrettyPrint` with `mixfix number rat format`, producing e.g. `assertEqual (3 ,add (1 ,2 )) passed.` — spaces around punctuation — whereas the README shows `assertEqual(3, add(1, 2)) passed.` Semantics unaffected. |
| C4 | README presents `cond` as required in `hasSolution`/`noSolution` | Low | The code accepts an empty bubble as `nil` condition (`T4 == 'bubble['nil.Qid]` → `nil`). |
| C5 | Legacy examples contradict the documented syntax | Medium | `testVasijas.maude`, `wrla18_test.maude`, and all `examples/geo2D/**/test-*.maude` use v1 syntax `(munit M is ... endu)` (parenthesized, LOOP-MODE-style, with `load ../mUnit.maude` and features `loop(...)`/`command(...)` that do not exist in the v2 grammar). They cannot be run with the current tool. |
| C6 | Version banner typo | Low | `mu-banner` contains the string `"Version 2.0 (October 23rd, \s2025)"`; `\s` is not a Maude escape and renders as `s`, so the banner prints "s2025" (verified in the session output). |

## Completeness Findings (gaps in the codebase / docs)

| # | Finding | Severity | Detail |
|---|---|---|---|
| G1 | No handling of `fileError` — missing-file `open` stalls silently | High | `MUNIT-IO` has rules for `openedFile`/`gotLine`/`closedFile` but none for `fileError`. Verified: `open examples/does_not_exist.maude` leaves the object in `state: reading` with an unconsumed `fileError(munit, fileManager, "No such file or directory")` message; `erew` returns and the session is dead with no user-visible error. |
| G2 | No handling of test-file grammar-parse failure — comments stall the session | High | `[parse-module]` only fires when `metaParse(MUNIT-GRAMMAR, ...)` succeeds; there is no failure branch (contrast `[parse-command-error]` for the prompt). Verified: a `***` comment anywhere in a test file makes the whole `munit ... endu` unparseable (`tokenize` does not strip comments — verified `'***` survives as a token), the object sticks in `state: processing`, and the session dies silently. |
| G3 | Dead code after `eof` in `io.maude` | Low | `set print attribute off .`, `erew run .`, `eof` are followed by `set print conceal on`, two `print conceal` commands, and `loop init-munit .`. After `erew` returns (user typed `q`), `eof` discards the rest, so those lines never execute. `init-munit` is undefined anywhere in the repository (verified: `loop init-munit .` → "bad token init-munit") — a leftover from the LOOP-MODE-based v1. |
| G4 | `load file.maude` placeholder is undocumented | Medium | First line of `io.maude`. If `file.maude` doesn't exist (the default), the load is **silently ignored** (verified — no error is printed), so the line works as an undocumented edit point for loading modules under test. README only describes the command-line-loading alternative. |
| G5 | No automated tests for the tool itself | Medium | No CI, no test runner, no regression suite. `examples/add_even_test.maude` (2 intentional failures) is the de-facto manual smoke test; `examples/reverse_list*.maude` are **untracked in git** (`git status` shows `??`). |
| G6 | Path arguments are single tokens | Low | `open_ : @Token@` and the `assertTrueMsg` message are length-1 bubbles; paths or messages containing spaces cannot be expressed. |
| G7 | Line-boundary token merging (theoretical) | Low | File lines are accumulated by string concatenation (`data: D + TXT`). Newlines are preserved (verified: `data:` shows `\n`), and typical assertion syntax self-delimits (`)` `,` split tokens — verified with `tokenize`), but a line ending mid-token adjacent to the next line's start could merge tokens. |
| G8 | `@NeTokenList@` declared but unused | Info | `MUNIT-SIGNATURE` declares `@NeTokenList@` and `MUNIT-GRAMMAR` defines `neTokenList`, but no assertion syntax uses it. |
| G9 | `assertEqual`/`assertDifferent` are `[comm]` | Info | Their two bubbles commute, so argument order in reports may vary. |
| G10 | `.agents/planning/` excluded | Info | Per user instruction, `.agents/planning` was excluded from this summary. |

## Language-Support Notes

- The codebase is 100% Maude; no language-support limitations affected this analysis.
- Analysis was performed by direct reading plus interpreter runs (end-to-end session, `tokenize` probes, missing-file probe, comment probe) — all findings marked "verified" reproduce on Maude 3.5.1.

## Recommendations

1. **Fix G1/G2** (highest value): add a `fileError` rule printing an error and returning to `idle`, and a `[parse-module-error]` rule handling `noParse` results (e.g. print "Test file not parsed" and re-prompt). Both are small rule additions to `MUNIT-IO` following the existing `[parse-command-error]` pattern.
2. **Clean up `io.maude`'s tail** (G3): remove the dead lines after `eof`, or move `loop init-munit .` out entirely.
3. **Update the README** (C1–C5): correct the entry-file name (`io.maude`), document `assertTrueMsg`, the optional search condition, the comment limitation (until G2 is fixed), and mark the legacy examples as v1-only.
4. **Track or remove** the untracked `examples/reverse_list*.maude` (G5).
5. Fix the banner typo (C6): `\s2025` → `2025`.

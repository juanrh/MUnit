## Project Snapshot

MUnit is an interactive unit-testing REPL for Maude 3.5.1 modules, written entirely in Maude. Users run `maude <module>.maude -allow-files io.maude`, then `open <test-file>` at the `MUnit>` prompt; test files are `munit MODULE is ASSERTIONS endu` declarations whose assertions (`assertEqual`, `assertTrue`, `hasSolution`, ...) are evaluated against the already-loaded module via META-LEVEL descent functions. Two source files: `mUnit.maude` (functional engine) and `io.maude` (grammar metaprograms + object-based I/O loop driven by `erew run .`).

## Critical Facts (verified empirically)

- The session is driven by `erew run .` at the end of `io.maude`; everything after the following `eof` line is dead code (`loop init-munit .` references an undefined constant).
- `***` comments in test files **break** the grammar parse and silently stall the session (no error branch for `[parse-module]`).
- `open` of a nonexistent file silently stalls (no `fileError` rule).
- `tokenize` does not strip comments; file lines accumulate with newlines preserved.
- The README's entry file name (`munit.maude`) is wrong — it's `io.maude` (loading `mUnit.maude`).
- `examples/geo2D`, `testVasijas.maude`, `wrla18_test.maude` use legacy v1 syntax incompatible with the current tool.
